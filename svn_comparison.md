### 1. Почему в Git ветвление «дешёвое», а в SVN — «дорогое»?

Разница заключается в архитектуре хранения данных внутри этих систем.

| Характеристика | Ветвление в Git (Дешёвое) | Ветвление в SVN (Дорогое) |
| :--- | :--- | :--- |
| **Что из себя представляет ветка** | **Простой текстовый файл** (указатель) объемом 41 байт, который содержит SHA-1 хэш коммита. | **Полная копия папки** проекта в репозитории на сервере. |
| **Скорость создания** | **Мгновенно**. Создается новый указатель, файлы на диске не копируются. | **Зависит от сети и сервера**. Сервер виртуально копирует дерево файлов (технология *Cheap Copies*). |
| **Переключение между ветками** | **Очень быстро**. Git просто меняет указатель `HEAD` и обновляет файлы в рабочей директории. | **Медленно**. Требуется скачать измененные файлы с сервера через команду `svn switch`. |
| **Слияние (Merge)** | **Автоматизировано**. Git отслеживает граф коммитов и точно знает общую точку разделения. | **Сложно**. SVN долгое время вообще не помнил историю слияний. Сейчас это работает лучше, но конфликты возникают чаще. |

### 2. Можно ли в SVN сделать коммит без интернета? Почему?

**Нет, в SVN нельзя сделать коммит без доступа к интернету** (или к локальной сети, где расположен центральный сервер). 

**Почему:**
SVN — это **централизованная** система контроля версий (VCS). У неё существует только одна база данных — на сервере. На вашем локальном компьютере хранится только рабочая копия файлов (Working Copy). 
Когда вы делаете `svn commit`, изменения должны немедленно записаться в центральную базу данных на сервере, а сервер должен присвоить коммиту следующий порядковый номер ревизии. Без связи с сервером эта операция технически невозможна.

### 3. В каких сценариях SVN до сих пор может быть предпочтительнее Git?

Несмотря на доминирование Git, SVN всё еще используется в индустрии (особенно в GameDev и корпоративном секторе) благодаря следующим особенностям:

* **Работа с огромными бинарными файлами (ассетами).** Git плохо справляется с файлами размером в гигабайты (3D-модели, текстуры, видео), так как каждому разработчику приходится скачивать всю историю их изменений. SVN скачивает только последнюю версию файла.
* **Блокировка файлов (File Locking / `svn lock`).** Бинарные файлы (например, файл локации в игре или PSD-макет) невозможно слить (merge) автоматически при возникновении конфликта. SVN позволяет разработчику «заблокировать» файл на сервере, чтобы никто другой не мог его редактировать, пока первый не закончит работу. В Git из-за его распределенной архитектуры полноценно заблокировать файл на сервере сложнее (хотя расширение Git LFS частично решает эту проблему).
* **Частичное скачивание (Narrow Checkouts).** В SVN вы можете скачать на компьютер не весь репозиторий, а только одну конкретную папку или подпроект. В Git вам в любом случае придется склонировать весь репозиторий целиком (хотя есть механизмы *sparse checkout*, они сложнее в использовании).
* **Авторизация на уровне папок.** В SVN можно настроить права доступа так, чтобы отдел маркетинга видел только папку `docs`, а программисты — папку `src`. В Git права выдаются сразу на весь репозиторий (для разделения приходится дробить проект на множество подмодулей `git submodule`).
