# Подготовка к КР №4 (Git)

## 1. Когда я выберу rebase, а когда merge? Почему?

Merge и rebase решают одну задачу — интегрировать изменения из одной ветки в другую, но делают это по-разному.

**Merge** создаёт merge-коммит с двумя родителями: история остаётся нелинейной, видно, что разработка шла параллельно. Существующие коммиты не переписываются, поэтому merge безопасен для общих веток.

**Rebase** переносит мои коммиты на вершину другой ветки, создавая их копии с новыми хешами: история становится линейной.

Выбор:
- rebase — для личных локальных веток перед merge/PR: чистая линейная история, легко читать git log, можно сквошить черновые коммиты;
- merge — для публичных/общих веток и когда важно сохранить факт слияния.

Золотое правило: never rebase public branches.

## 2. Что произойдёт, если я сделаю rebase публичной ветки, с которой работают коллеги?

Rebase переписывает историю: каждый существующий коммит заменяется копией с новым хешем. У коллег в их локальных копиях останутся старые коммиты.

После force-push истории расходятся. Когда коллеги сделают pull, Git поставит «новые» коммиты рядом со старыми: появятся дубли и конфликты, их работа сломается. Разбираться придётся вручную.

Поэтому публичные ветки обновляют только через merge, а откатывают через revert; rebase — только для личных локальных веток.

## 3. Зачем нужен multi-remote и в каких реальных сценариях он применяется?

Multi-remote — это когда у одного локального репозитория несколько удалённых.

Сценарии:
- зеркало/бэкап: основной на GitHub, зеркало на GitLab (наш случай) — отказоустойчивость;
- миграция между платформами;
- open-source: fork + upstream;
- разные команды на разных хостингах.

Настройка: git remote add <имя> <URL>; одному remote можно назначить несколько push-URL (git remote set-url --add --push), тогда один git push отправляет в оба. В нашем репозитории origin пушит в GitHub и GitLab одновременно.

## Итог

- Личные ветки: rebase + squash — чистая история.
- Публичные ветки: merge/revert — история не переписывается.
- Multi-remote: один push — в несколько хостингов.
